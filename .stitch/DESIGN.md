# Design System: SwiftCare

**Product:** SwiftCare GeoAgent — Emergency Ambulance Routing  
**Source of truth:** This file (`.stitch/DESIGN.md`)  
**Implementation tokens:** `app/globals.css` + shadcn/ui (New York)  
**Route semantics:** `lib/routing-constants.ts`

> Every newly generated Stitch screen and every frontend implementation derived from Stitch **must** follow this document. Do not invent page-specific colors, type scales, radii, or component styles unless a domain rule below requires it (map corridors, severity, live status).

---

## 1. Visual Theme & Atmosphere

SwiftCare is a **tactical emergency operations** product. The UI must feel calm under pressure: cool blue-white surfaces in light mode, deep navy command-center surfaces in dark mode. Density is purposeful—control-room dashboards pack operational data, while marketing surfaces stay clearer. Visual noise is forbidden; attention belongs to **status, ETA, corridors, and hazards**.

The brand personality is **dependable, precise, and high-stakes**. Surfaces are quiet and layered (card on muted canvas), not glass-heavy or decorative. Elevation is whisper-soft. Motion is short and functional (theme cross-fade ~300ms, alert slide-in). Color is semantic first: red means life-critical, amber means caution, emerald means clear/affirmative, blue means primary action or planned corridor.

**Do not recreate marketing-only flourishes** (gradient hero wordmarks, emerald-only landing CTAs, cyan role accents) as the app-wide language. Marketing may use a darker cinematic hero overlay, but product chrome, forms, dashboards, and driver HUD all share one token set.

Do not introduce page-local cyan, indigo, rose, teal, or zinc scales for product UI. Map ad-hoc hues back to `primary`, `critical`, `warning`, `success`, `route-*`, or neutrals above.

## 3. Typography Rules

### Families

| Role | Family | Character |
|:---|:---|:---|
| **Display / headlines** | **Plus Jakarta Sans** (`font-display`) | Confident, rounded geometric; used for page titles, stats, hero |
| **UI / body** | **Inter** (`font-sans`) | High x-height operational reading |
| **Data / caps labels** | **JetBrains Mono** (`font-mono`) | IDs, ETA, timestamps, corridor badges, uppercase status |

### Hierarchy & Weights

- **Display:** 36–48px (marketing up to 60px), weight 800, tracking tight (−0.02em)
- **Headline:** 20–24px, weight 700
- **Title / emphasis:** 14–16px, weight 600–700
- **Body:** 14px default in dense dashboards; 16px for marketing/support copy
- **Labels:** 11–12px, weight 600–700; mono labels use uppercase + wide tracking
- **Stats:** Display face, weight 800, mono allowed for ETA/km figures

Weights in use: **400** (body), **500–600** (UI medium), **700** (emphasis), **800** (display/stats). Avoid 900 except rare mono badge stamps.

### Spacing Principles

- Line height stays readable: ~1.4–1.5 for body, tighter (~1.05–1.15) for display
- Section titles sit above content with `md`–`lg` gap; meta captions use muted color
- Mono labels never carry long prose—keep them short status strings

---

## 4. Spacing, Sizing & Shape

### Spacing scale

Strict **4px baseline**: `4 / 8 / 16 / 24 / 32 / 48`.  
Card padding default **16px**; larger operational panels **20–24px**. Page gutters: **16px** mobile, **24–32px** desktop. Content max width **1280px** (`max-w-7xl`).

### Border radius

Base `--radius: 0.75rem` (12px). Derived:

| Use | Radius |
|:---|:---|
| Buttons (default) | `rounded-lg` (~12px) |
| Inputs | `rounded-xl` (~16px) |
| Cards / panels | `rounded-xl` to `rounded-2xl` |
| Status chips / badges | `rounded-full` (pill) |
| Icon wells | `rounded-lg` or `rounded-md` |
| Map popups | ~12px (match cards) |

Avoid sharp corners and avoid fully circular primary buttons (icon-only controls may be square with radius).

### Shadows & elevation

1. **Base canvas** — flat background  
2. **Cards** — hairline border + whisper shadow (`xs` / `sm`)  
3. **Raised panels / map chrome** — `md` shadow + `backdrop-blur` + translucent surface  
4. **Modals / critical alerts** — stronger shadow (`lg`); driver reroute alerts may use ring emphasis with success border  

Prefer border + surface shift over heavy drop shadows. No neon glow as decoration.

## 5. Surfaces

| Layer | Treatment |
|:---|:---|
| **Page** | `bg-background text-foreground` |
| **Card / panel** | `bg-card border border-border rounded-2xl` + quiet shadow |
| **Nested item** | `bg-background/50` or `surface-raised` inside card |
| **Sticky header** | `bg-card/95` or `bg-background/90` + `backdrop-blur-md` + bottom border |
| **Map overlay** | Same as sticky header; high z-index; never opaque black blocks that hide map context |
| **Modal scrim** | Navy at ~40% + light blur |

Dark mode Leaflet tiles use inverted tactical basemap styling; keep overlay chrome on token surfaces so contrast holds.

## 6. Component Stylings

### Buttons (shadcn)

| Variant | Look | Use |
|:---|:---|:---|
| **default** | Solid Operational Blue, white label | Primary actions |
| **secondary** | Soft mist fill | Supporting actions |
| **outline** | Border + transparent/background | Cancel, secondary |
| **ghost** | No border, muted hover | Toolbar / compact chrome |
| **destructive** | Soft red fill + critical text (not solid red wall) | Dangerous actions |
| **link** | Primary text + underline on hover | Inline navigation |

Sizes: compact operational (`h-8` default); use **min-height 44px** for driver HUD and any gloved/vehicle context. Corner: `rounded-lg`. Transitions short; active press may translate 1px. Focus: ring + border using `ring` token.

Affirmative life-saving accepts (e.g. “Follow New Route”) may use **success** fill—this is domain emphasis, not a second primary brand.

### Cards

- Container: `rounded-2xl border bg-card p-4` (or `p-6` for major panels)
- Optional left accent bar (`border-l-4`) for severity/route tone only
- Header: icon well (`size-7–8`, rounded-lg, tinted token bg) + bold title + muted meta
- Hover on interactive cards: slightly stronger shadow or primary-tinted border—no scale bounce on dense lists

### Inputs & Forms

- Height comfortable (`py-2.5`), `rounded-xl`, `border-border`, soft muted fill
- Focus: primary-tinted border + light ring (`ring-primary/30`)
- Labels always visible (not placeholder-only)
- Errors: critical text + `aria-invalid` ring; helper text muted
- Demo/role pickers use semantic borders (primary/success/warning)—not rainbow accents

### Badges & Status Indicators

- Pill shape (`rounded-full`), `text-xs`, semibold/bold
- Variants: default (primary), secondary, destructive, outline
- Operational status examples:
  - **Emergency Active** — critical tint bg + border + siren icon + label
  - **Standby / Live** — success tint + pulsing or solid dot + label
- Route badges reuse `route-*` tint classes from routing constants

### Tables

- Compact `text-sm`, header row bottom border, row hover `muted/50`
- Numeric/ETA cells prefer `font-mono`
- Keep zebra optional; prefer hover + selection state
- Horizontal scroll wrapper on small screens

### Alerts

- `rounded-lg border px-4 py-3`, role=`alert`
- Default: card surface  
- Destructive: critical text emphasis  
- Driver reroute: elevated dark panel, success border/ring, large dual actions (≥44px)

### Navigation

- **Marketing header:** sticky, blurred background, height 56px, BrandLogo left, text actions right  
- **Dashboard topbar:** same height; logo + context title; segmented nav in muted well; theme toggle; user menu  
- **Active nav:** primary fill or primary text on muted segment  
- **Mobile:** hamburger → full-width sheet/drawer; touch targets ≥44px  
- Do not invent a second nav visual language per role—same chrome, different links

### Dialogs / Sheets

- Card surface, `rounded-xl`+, overlay scrim navy/40  
- Clear title, muted description, footer actions right-aligned on desktop  
- Sheets for mobile filters / driver bottom sheets: grab-friendly padding

---

## 7. Map-Related UI

- Map is the spatial source of truth; chrome must stay translucent and legible
- **Legend:** bottom-left overlay, `w-72`, collapsible, card/95 + blur, uppercase title
- **Controls:** compact buttons with primary selected state
- **Popups:** 12px radius, soft deep shadow, hairline border
- **Attribution / brand chip:** tiny mono badge, muted
- Corridor colors **must** match Section 2 map semantics and `ROUTE_SEMANTICS`
- Loading states: muted panel + mono “Initializing…” style copy—no skeleton rainbows

---

## 8. Emergency UI Patterns

| Pattern | Treatment |
|:---|:---|
| **Emergency Active** | Critical pill + icon; never silent color-only |
| **Standby / Clear** | Success pill + dot |
| **Reroute recommendation** | High-emphasis alert; success CTA to accept; outline to dismiss |
| **Incident / hazard** | Critical or warning tone; dashed empty states for “no incidents” |
| **ETA / delay stats** | Display or mono numerals; tone via `critical` / `warning` / `success` / `route-*` |
| **Timeline events** | Mono timestamps; severity dot using status tokens |
| **Decision approval** | Primary for confirm operational choice; destructive for reject when needed |

Keep urgency in **status components**, not in vibrating backgrounds or continuous full-screen flash.

## 9. Light Theme & Dark Theme

| Concern | Light | Dark |
|:---|:---|:---|
| Mood | Professional clinical white-blue | Tactical navy command center |
| Primary interactivity | Deeper blue `#1769aa` | Brighter sky `#0ea5e9` |
| Borders | Cool gray-blue solid | Low-opacity white |
| Cards | White + faint navy-tinted shadow | `#0f1626` + soft black shadow |
| Map tiles | Standard OSM/light tiles | Inverted tactical filter on tile pane |
| Theme switch | Cross-fade via `html.transitioning` (~300ms) | Same |

Implement through CSS variables in `app/globals.css` (`:root` / `.dark`). Components consume semantic tokens (`bg-background`, `text-primary`, `bg-critical`)—never hard-code theme hex in JSX except map geometry colors from routing constants.

## 10. Layout Principles

### Grid & Structure

- Max content width **1280px**, centered
- Control room: map-forward split (map dominant + side panels)
- Driver: map full-bleed + bottom sheet / floating alerts
- Marketing: single-column hero → sectioned content

### Whitespace

- Dashboards: tighter, information-dense, consistent card gaps (`gap-3`–`gap-4`)
- Marketing: larger section spacing (`py-16`–`py-20`)
- Never mix both densities on one surface without hierarchy

### Responsive Behavior

- Mobile-first Tailwind breakpoints: `sm 640`, `md 768`, `lg 1024`, `xl 1280`
- Collapse multi-column panels to stacked sheets below `lg`
- Topbar nav hides behind menu below `lg`
- Touch targets ≥ **44×44px** on driver and primary mobile actions
- Map legend: `max-w-[calc(100vw-24px)]` so it never clips off-screen

---

## 11. Accessibility Principles

- **Focus:** visible `*:focus-visible` outline using `ring` (2px + offset); never `outline-none` without replacement
- **Contrast:** text on surfaces must meet WCAG AA; muted text only for non-essential meta
- **Color independence:** status always includes text and/or icon
- **Hit targets:** 44px minimum for critical driver actions
- **Motion:** respect reduced motion for decorative animation; keep state changes perceivable
- **Semantics:** alerts use `role="alert"`; expanders expose `aria-expanded`; icon-only buttons need `aria-label`
- **Theme:** support light and dark; honor `color-scheme`
- **Map a11y:** legend labels explain corridor meaning in words, not emoji alone

## 13. Normalization Notes (intent vs. legacy drift)

Extracted from the live codebase, then **normalized**:

- Kept the intentional dual theme, brand navy, operational primary, severity trio, and corridor semantics  
- Collapsed inconsistent one-off cyan/indigo/zinc/teal page accents into semantic tokens  
- Treat landing emerald CTAs as marketing emphasis; product primary actions use Operational Blue (success reserved for affirmative/live states)  
- Unified radius around 0.75rem base and quiet elevation  
- Single typography stack: Plus Jakarta Sans + Inter + JetBrains Mono  

This document describes the **intended** SwiftCare design language for all future Stitch generation and frontend work.
