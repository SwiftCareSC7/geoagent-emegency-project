# Auto-Commit to GitHub Every 1 Minute

This skill keeps a local git repository in continuous sync with a GitHub remote by:

1. Polling the working tree every **60 seconds**.
2. Detecting any tracked or untracked changes.
3. Auto-staging, auto-committing with a **detailed, multi-line message**, and pushing to the configured remote.
4. Generating commit messages that describe **what changed, where, why it matters**, in the context of the GeoAgent Emergency project (or any project, when configured).

Default target remote: `https://github.com/SwiftCareSC7/geoagent-emegency-project.git`

## When to use

- User says "commit every 1 min", "auto commit", "push to github automatically", "watch and commit", "background git sync".
- User wants a daemon / background process that continuously mirrors local edits to a remote.
- User wants detailed, human-friendly commit messages (not just "auto commit").

## When NOT to use

- One-off manual commits (just use `git commit` directly).
- Repositories where auto-commits are forbidden by branch protection rules.
- CI/CD pipelines that already auto-commit (use those instead).

## Architecture

The skill is split into a **macOS launchd job** (recommended, survives reboot) or a plain background `bash` loop (fallback). Both call the same Node.js helper that builds detailed commit messages from `git diff` output.

```text
                   every 60s
       ┌───────────────────────────────┐
       ▼                               │
  launchd (com.user.auto-commit)       │
       │                               │
       ▼                               │
  scripts/auto-commit.sh               │
       │                               │
       ├─► git fetch origin            │
       ├─► git add -A                  │
       ├─► git diff --cached --stat     │──► generates rich message
       ├─► git commit -m "..."         │    (scripts/build-message.js)
       └─► git push origin <branch>    │
                                       │
       on failure: log + retry next tick
```

## Detailed Commit Message Format

Every auto-commit produces a message of this shape, generated by `scripts/build-message.js`:

```text
<type>(<scope>): <short summary>

- <file1>: <what changed in this file, in plain English>
- <file2>: <what changed in this file, in plain English>
- ...

Affected areas:
  - <subsystem A>: <count> file(s)
  - <subsystem B>: <count> file(s)

Stats: +<insertions> / -<deletions> across <files> file(s)

Auto-commit @ <ISO timestamp> | tick #<N>
```

`<type>` is inferred from the changed paths using `references/commit-conventions.md`:

| Path prefix | Type |
|---|---|
| `server/modules/**` | `feat(server)` |
| `server/test-*` | `test(server)` |
| `app/**`, `components/**`, `lib/**` | `feat(frontend)` |
| `routing-engine/**` | `feat(routing)` |
| `docs/**` | `docs` |
| `*.md` at root | `docs` |
| `*.json`, `*.yaml`, `*.yml` | `chore(config)` |
| anything else | `chore` |

`<scope>` is the top-level folder that received the most changes.

`<short summary>` is a 1-line phrase generated from the most-changed file and the diff hunks.

The bullet list contains **one line per file** that changed, summarising the nature of the edit (added / removed / renamed / modified) and the dominant change kind (function added, import updated, config tweak, etc.).

## Configuration

Edit the top of `scripts/auto-commit.sh` if you need to override defaults:

```bash
REPO_DIR="/Users/priyanshu/Documents/geoagent-emegency-project"
BRANCH="main"
REMOTE="origin"
INTERVAL_SECONDS=60
LOG_FILE="$SKILL_DIR/assets/auto-commit.log"
```

To commit to a different remote / repo, change `REMOTE` and `BRANCH`.

## Safety Guarantees

- **Nothing is committed unless `git status` shows a change.** Empty commits are skipped silently.
- **Push is skipped** when offline or when the remote rejects (network errors are logged and retried next tick).
- **No force pushes.** Only `git push <remote> <branch>` is ever run.
- **No branch is auto-created.** Push targets the existing local branch.
- **No secrets are touched.** `.env` files are NOT in `.gitignore` by default; if you keep secrets locally, add them to `.gitignore` BEFORE starting the daemon. See `references/commit-conventions.md` for a sample `.gitignore` snippet.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `launchd` job does not start | `~/Library/LaunchAgents` not writable | Run `install-launchd.sh` again as your user (not root) |
| `Authentication failed` on push | HTTPS remote needs PAT | `git credential-osxkeychain` or embed a PAT in the remote URL |
| Every tick logs "no changes" | Working tree clean | Expected — script no-ops when clean |
| Commit messages look generic | Diff is too large | Skill summarises at file level; check `references/commit-conventions.md` |
| Two ticks race and double-commit | Two daemons running | `launchctl list \| grep auto-commit` — should show exactly one |

For deeper notes on launchd quirks (sleep, network reachability, code signing), see `references/launchd-notes.md`.
